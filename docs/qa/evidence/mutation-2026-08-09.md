# Selective mutation baseline — 2026-08-09

## Scope

The release configuration now targets current trust-critical code instead of
the retired forecaster: policy authority decisions, journal integrity, and
durable ingest watermarks. The focused tests are declared in `pyproject.toml`.

## Offline result

`mutmut 3.5.0` generated and executed 712 mutations against the selected code:

- 337 killed
- 274 survived
- 95 timed out
- 6 had no covering test

The run is a baseline, not a passing mutation score. It found that the regular
suite strongly exercises end-to-end states but often does not assert every
diagnostic string, intermediate digest material, or failure branch precisely
enough to kill Mutmut's fine-grained replacements. This is retained as an
explicit quality risk rather than being hidden behind the green functional
suite.

## Release interpretation

The deterministic mutation-class journey through the installed wheel did pass:
rewriting the first chained journal entry changed `forecost verify --json` from
`intact` to `rewritten`, identified sequence 1, and returned exit code 1. The
functional integrity contract is therefore evidenced. A future mutation-score
gate should first classify equivalent mutations and replace timeout-prone
whole-module mutation with a curated must-kill set.
